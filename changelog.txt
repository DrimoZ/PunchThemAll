PunchThemAll changelog
======================

The full, maintained changelog is CHANGELOG.md in the repository. This file is the short version
pasted onto the CurseForge/Modrinth release page.


1.21.1-2.4.0
------------

New

* Tooltips you can actually read, in two lengths. An interaction can carry a dozen facts, so the
  transformation slot now shows a summary and keeps the full breakdown behind a key you hold.
  Which key is yours: detail_key in the new pta-client.toml is shift, control, alt, always or never.
* conditions.neighbours gates an interaction on the blocks around the target. "require" asks about a
  block a transformation will change; this asks whether the recipe applies at all. "invert" for
  "and not".
* Regions. An offset can name a second corner with "to" and covers the whole box between the two,
  corners included. A 3x3 excavator is one entry rather than nine.
* A chance for a whole set: "transformation": { "chance": 0.7, "all": [ ... ] }. Either the pattern
  appears or it does not, instead of appearing half-built.
* "into": { "kind": "copy" } writes whatever block is already somewhere, rather than naming one,
  with "from" to say where to read it. A copy plus a break is a block that moves.
* rewards.at moves where the drops land, for an interaction that acts somewhere other than the
  block you clicked.
* "drops": "tool" on a break gives the block's loot as broken by the held item, Fortune and Silk
  Touch included.
* max_drop_rows in pta-client.toml caps how tall a recipe box gets.
* Thirteen more worked examples, and two new documents: what the mod can and cannot do, and whole
  recipes by goal.

Changed

* A recipe no longer inherits the height of the widest one in the category. One interaction with
  thirty drops used to make every other one three rows tall. The box is capped, and the drops past
  the cap share a slot that cycles through them — nothing hidden, nothing to scroll. Guaranteed and
  weighted drops are laid out separately, guaranteed first, so a square never alternates between
  what you always get and a one-in-four chance.

Fixed

* Regions never worked. "at.to" parsed and the box maths was right, but the two were never
  connected, so every region collapsed to a single block.
* JEI and EMI crashed on a "copy" transformation, taking the whole recipe down with them.
* The sneak requirement was shown in two places that could disagree: a recipe could demand shift
  with no shift in its tooltip, next to one showing the wrong figure. It belongs to the type.
* An interaction whose requires_sneaking disagreed with its type could never fire, silently.
* An unresolvable sound, particle or biome entry is now reported instead of dropped in silence.


1.21.1-2.3.0
------------

New

* Transformations can act on a block other than the one you clicked, and can break or place rather
  than only overwrite. "op" is "replace" (the old behaviour, still the default), "break" (destroys
  the block with its particles, its sound and its loot) or "place" (writes only where there is room
  and where the block can stay). "at" moves the destination: x is right, y is up, z is forward, read
  in world axes, against the player's facing, or out of the clicked face.
* "require" gates a transformation on what the destination already is, using the same syntax as
  "target".
* "transformation" also accepts a list, applied in order, each entry rolling its own chance. Every
  destination is checked against the world as it was when you clicked, so declaration order does not
  change the outcome.
* Air-target interactions can carry transformations when they are offset — their origin is the
  player, so "place a block above me" now works.
* Four config keys under PunchThemAll.Interactions: allow_offset_transformations,
  max_transformation_offset, max_transformations_per_interaction and fire_protection_events.
* In-world automated tests, running on a headless server.

Changed

* Transformations post block break/place events, so claim and protection mods can veto them. This
  matters now that a transformation can reach a block the player never pointed at. Server owners
  also get a hard distance cap.
* A click transforms any one block at most once, instead of performing at most one transformation.
  Two interactions on the same click no longer block each other when they act on different blocks.
* JEI and EMI describe the operation, the offset and the requirement in the tooltip. The slot alone
  read as "this block becomes that", which is untrue for a break, an offset or a list.

Fixed

* "op": "place" refuses a destination where the block could not survive, instead of placing it and
  letting the next block update pop it.
* Two entries of one transformation list aimed at the same block no longer both apply.
* A transformation reaching outside the world height or into an unloaded chunk is skipped. Chunks
  are never force-loaded from a click.
* Every refusal is reported under Debug.log_skipped_interactions, naming the block and the reason.


1.21.1-2.2.0
------------

New

* "hidden": true on an interaction keeps it out of JEI and EMI while it still loads and still fires.
  For secrets, and for the middle steps of a multi-stage recipe. Not the same as "enabled": false,
  which turns an interaction off.
* 241 automated tests over the matching, drop and loading logic.

Fixed

* A malformed id in sound, particles, effects or fortune no longer aborts the whole datapack load —
  one typo used to cost the pack every interaction. Same for a malformed biome #tag, which threw on
  every click.
* count: {min: 0, max: 3} on a drop now means "nothing to three". It used to mean "never anything",
  while still taking up its weight in the pool.
* An nbt whitelist/blacklist that expects a different shape than the item has no longer crashes
  mid-click.
* When several interactions match one click, which ones run is now deterministic instead of varying
  between runs.
* Fortune can no longer produce a stack larger than the item allows.
* JEI no longer churns its whole category on every /reload.
* Leaving a server clears its interactions, instead of showing them on the main menu and in the next
  world.
* Cooldown bookkeeping for fake players no longer grows for the life of the server.

Changed

* Clients without PunchThemAll can now join a PunchThemAll server (they just see no PTA entries in
  JEI/EMI). The network protocol version changed: a 2.1.0 client cannot talk to a 2.2.0 server.
* The interaction sync is sent in batches, so a large pack no longer risks dropping clients at join.
